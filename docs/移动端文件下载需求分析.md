# 移动端文件下载需求分析

## 1. 引言
在移动应用中，用户经常需要远程访问服务器上的文件资源，并进行选择性下载至本地以便离线使用。本需求针对“通过接口获取服务端文件目录，在移动端界面展示，并支持导航、元信息查看、单个/批量下载，且本地目录结构与服务端严格一致”的场景，进行详细的功能、交互、技术实现及异常处理分析。

## 2. 总体目标
- **功能完整性**：实现服务端文件目录的树形/列表化展示，包含名称、类型、大小、修改时间等元数据；提供直观的目录导航（点击进入、面包屑/返回上级）。  
- **下载一致性**：支持将文件下载到移动端沙盒目录中，且本地文件夹层级、文件命名完全镜像服务端目录结构。  
- **下载灵活性**：支持单个文件下载和同时下载多个文件（多选批量）。  
- **可靠性与体验**：处理网络异常、存储空间、权限、并发控制等，并提供进度反馈。

## 3. 功能性需求详细描述

### 3.1 服务端目录获取与列表展示
**输入**：当前目录标识（如相对路径 `/` 或 `folderId`）  
**处理**：
- 请求接口获取当前目录下的所有子条目（子目录与文件）。
- 每个条目至少包含以下字段：
  - 名称（name）
  - 类型（type: `dir` / `file`）
  - 大小（size，仅文件有效，目录可为0或省略）
  - 最后修改时间（lastModified）
  - 下载地址（downloadUrl，仅文件有效）
  - 相对根目录的路径（relativePath，用于构建本地目录结构）
- 解析后按“目录优先，同类型按名称排序”展示。

**展示要求**：
- 使用列表视图（如 `List` ）显示。
- 目录和文件使用不同图标区分。
- 每行展示名称、类型（文件图标）、大小（格式化）、修改时间。
- 支持下拉刷新当前目录内容。

### 3.2 目录导航与路径切换
**行为**：
- 点击文件夹条目 → 进入该文件夹，重新加载并展示其内部内容。
- 提供面包屑导航（例如：`根目录 / 文档 / 项目报告`）点击任一级别即可快速跳转。
- 提供“返回上级”按钮（当不在根目录时显示）。
- 当前路径位置需清晰显示。

### 3.3 文件下载到本地沙盒并保持服务器目录结构
**目录结构镜像规则**：
- 移动端应用沙盒内指定一个根目录（例如 `Documents/ServerMirror`）作为所有下载文件的本地根。
- 对于服务端相对路径为 `folderA/sub/file.pdf` 的文件，下载后应保存在 `SandboxRoot/folderA/sub/file.pdf`。
- 若中间目录不存在，需递归创建。

**实现要点**：
- 每个文件的下载任务包含：
  - 源 URL（从接口获取的 `downloadUrl`）
  - 目标绝对路径（本地沙盒根 + 相对路径）
- 下载前检查目标路径所在目录是否存在，不存在则调用文件系统 API 创建目录。
- 支持覆盖策略：默认提示用户是否覆盖；也可以采用自动重命名或跳过（可配置）。

### 3.4 单个及多个文件下载支持
#### 3.4.1 单个下载
- 每个文件条目右侧提供“下载”按钮（或长按菜单）。
- 点击后启动单个下载任务，显示下载进度（进度条或百分比），任务完成后更新状态。

#### 3.4.2 多文件批量下载
- 列表支持进入“编辑/多选模式”（长按或点击编辑入口），每个条目显示复选框。
- 提供“全选/取消全选”功能。
- 选中多个文件（仅文件可被选中；目录若被选中，根据需求可扩展为递归下载目录下所有文件，此处作为增强建议）后，点击“下载选中文件”按钮。
- 批量下载时同时发起多个下载请求，但需注意并发控制（建议同时最多 2~3 个任务，其余排队）。
- 提供批下载整体进度（已完成数/总文件数）及每个文件独立进度。

### 3.5 下载管理
- **下载队列**：管理等待、进行中、已完成、失败的任务。
- **任务状态**：等待、下载中、暂停、完成、失败。
- **进度通知**：实时更新任务进度（字节维度），并在界面上体现（可独立设计下载管理页面，或在文件列表中对应文件旁显示）。
- **用户操作**：支持暂停/恢复/取消单个任务或全部任务。
- **存储空间检查**：批量下载前预估所需空间，不足时提示用户并停止。
- **失败重试**：对网络异常、服务器错误等任务提供自动重试机制（默认重试 3 次，间隔指数退避），或者允许用户手动重试。

## 4. 非功能性需求

| 类别     | 要求                                                         |
| -------- | ------------------------------------------------------------ |
| 性能     | 目录列表加载时间 < 1 秒（弱网下显示骨架屏）；支持分页或虚拟滚动以处理大目录。 |
| 并发限制 | 同时下载任务数 ≤ 3，避免耗尽网络连接和 I/O 资源。            |
| 存储占用 | 下载前检查剩余空间，低于阈值（如 50MB）时禁止新下载并提示清理 |
| 可用性   | 提供清晰的状态反馈（加载中、空目录、错误提示）；断网时有友好提示并支持网络恢复重连。 |
| 离线能力 | 下载完成后文件可永久保存在沙盒中，应用重启后仍可访问（除非用户主动删除）。 |

## 5. 接口定义

## 1. 获取文件列表

```
GET /api/files?path=<relativePath>
```

获取指定目录下的文件和文件夹列表，文件夹排在前面，按名称字母排序，隐藏文件（以 `.` 开头）不显示。

### 请求参数

| 参数   | 位置  | 类型   | 必填 | 说明                                       |
| ------ | ----- | ------ | ---- | ------------------------------------------ |
| `path` | query | string | 否   | 相对根目录的路径，空字符串或不传表示根目录 |

### 响应 200

```json
{
  "path": "",
  "files": [
    { "name": "documents", "type": "dir",  "size": 0,   "mtime": "2026-04-30T02:20:54.814Z" },
    { "name": "images",    "type": "dir",  "size": 0,   "mtime": "2026-04-30T02:20:55.068Z" },
    { "name": "readme.txt","type": "file", "size": 10,  "mtime": "2026-04-30T02:20:55.260Z" }
  ]
}
```

### 字段说明

| 字段    | 类型   | 说明                                  |
| ------- | ------ | ------------------------------------- |
| `name`  | string | 文件/文件夹名称                       |
| `type`  | string | `"dir"` 表示文件夹，`"file"` 表示文件 |
| `size`  | number | 文件大小（字节），文件夹为 0          |
| `mtime` | string | ISO 8601 格式的最后修改时间           |

### 错误码

- `400 PATH_TRAVERSAL` — 路径越权访问被拒绝
- `404 DIR_NOT_FOUND` — 目录不存在

## 2. 获取文件/目录信息

```
GET /api/files/info?path=<relativePath>
```

获取单个文件或目录的元信息。

### 请求参数

| 参数   | 位置  | 类型   | 必填 | 说明             |
| ------ | ----- | ------ | ---- | ---------------- |
| `path` | query | string | 是   | 相对根目录的路径 |

### 响应 200

```json
{
  "name": "readme.txt",
  "type": "file",
  "size": 10,
  "mtime": "2026-04-30T02:20:55.260Z"
}
```

## 3. 单文件下载

## 

```
POST /api/download
Content-Type: application/json
```

将文件以流式方式直接下载到本地。响应为二进制文件流。

### 请求 Body

```json
{
  "path": "documents/report.pdf"
}
```

| 字段   | 类型   | 必填 | 说明             |
| ------ | ------ | ---- | ---------------- |
| `path` | string | 是   | 源文件的相对路径 |

### 响应格式

`Content-Type: application/octet-stream`

响应为文件的原始二进制流。文件名通过 `Content-Disposition` 响应头返回。

### 错误码

- `400 NOT_A_FILE` — 只能下载文件
- `404 FILE_NOT_FOUND` — 源文件不存在
- `507 ENOSPC` — 磁盘空间不足

### 移动端调用示例

```javascript
// 下载文件到移动端
const resp = await fetch('http://192.168.1.100:3000/api/download', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    path: 'documents/report.pdf',
  }),
});

if (!resp.ok) {
  const err = await resp.json();
  throw new Error(err.message);
}

const blob = await resp.blob();
const url = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url;
a.download = resp.headers.get('Content-Disposition').match(/filename="?(.+?)"?$/)[1];
document.body.appendChild(a);
a.click();
document.body.removeChild(a);
URL.revokeObjectURL(url);
```

## 4. 批量下载

```
POST /api/download/batch
Content-Type: application/json
```

批量下载多个文件/文件夹。支持文件和文件夹混合选择，所有文件会实时打包为 ZIP 压缩包并通过网络流式传输到客户端。

### 请求 Body

```json
{
  "paths": ["documents/report.pdf", "images/", "readme.txt"]
}
```

| 字段    | 类型     | 必填 | 说明                            |
| ------- | -------- | ---- | ------------------------------- |
| `paths` | string[] | 是   | 相对路径数组，可混合文件/文件夹 |

### 响应格式

`Content-Type: application/zip`

响应为 ZIP 压缩包的二进制流。下载的文件名为 `download.zip`。

### 错误码

- `400 INVALID_PATHS` — 请选择至少一个文件或文件夹
- `400 NO_FILES` — 所选项目中无文件可复制
- `400 PATH_TRAVERSAL` — 路径越权访问被拒绝
- `507 ENOSPC` — 磁盘空间不足

### 移动端调用示例

```javascript
// 批量下载为 ZIP 压缩包
const resp = await fetch('http://192.168.1.100:3000/api/download/batch', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    paths: ['documents/report.pdf', 'images/', 'readme.txt'],
  }),
});

if (!resp.ok) {
  const err = await resp.json();
  throw new Error(err.message);
}

const blob = await resp.blob();
const url = URL.createObjectURL(blob);
const a = document.createElement('a');
a.href = url;
a.download = 'download.zip';
document.body.appendChild(a);
a.click();
document.body.removeChild(a);
URL.revokeObjectURL(url);
```

| 400         | `INVALID_DEST`   | 目标路径不能为空                              |

## 6. 移动端关键技术实现要点

### 6.1 本地沙盒目录结构维护
- **确定本地根目录**：  。  
- **创建相对路径目录**：使用 `File` API递归创建 `mkdirs()`。
- **文件写入**：使用流下载并直接写入目标文件，避免先写临时目录再移动（但建议先下载到临时 `.tmp` 文件，下载完成后再 rename 到目标名称，防止下载中断产生损坏文件）。

### 6.2 多下载任务并发控制与队列
- 使用 **协程/异步任务队列**。
- 设计 `DownloadManager` 单例：
  - 维护一个优先级队列（FIFO）。
  - 最多同时运行 N 个任务（N = 2 或 3）。
  - 每个任务实现 `Runnable`/`Operation`，包含下载、进度回调、完成/错误处理。
  - 支持批量添加任务，批量启动。

## 7. 流程简述（用户视角 + 技术流）

### 场景1：浏览并下载单个文件
1. 用户打开文件管理页面 → 请求根目录内容 → 展示列表。
2. 用户点击文件夹“项目A” → 请求该文件夹内容 → 更新列表。
3. 用户点击文件“汇报.pptx”旁的下载按钮 → 调用 `DownloadManager.addDownload(item)`。
4. `DownloadManager` 创建任务，检查本地是否存在相同路径文件；若存在则弹窗“已存在，是否覆盖？”。
5. 开始下载，更新进度，下载完成后提示用户，并标记文件为“已下载”。

### 场景2：多选批量下载
1. 用户长按列表进入多选模式，勾选多个文件。
2. 点击底部“下载选中”按钮 → 收集所有选中文件的 `FileItem` 列表。
3. 调用 `DownloadManager.addBatchDownload(fileItemList)` 批量加入队列。
4. 队列依次（控制并发数）处理下载，UI 显示批量总进度和每个文件状态。
5. 所有任务完成后，显示下载完成通知，并提供“查看本地文件”入口。

## 8. 异常场景及处理策略

| 异常场景                                        | 处理策略                                                     |
| ----------------------------------------------- | ------------------------------------------------------------ |
| 获取目录列表时网络断开                          | 显示错误提示及“重试”按钮，不展示陈旧缓存（或显示缓存并提醒“数据可能过期”）。 |
| 下载过程中网络中断                              | 自动暂停当前任务，网络恢复后自动恢复下载（需支持断点续传，服务端应支持 Range 头）。 |
| 服务器返回的文件大小与本地空间不足              | 在开始下载前通过 `Content-Length` 或接口返回的 size 字段对比剩余空间，不足时拒绝下载。 |
| 服务端目录结构与本地结构冲突                    | 若下载时发现目标路径已存在同名文件但并非由下载任务创建（外部修改），提供覆盖/保留选项。 |
| 路径遍历攻击（例如 relativePath 包含 `../../`） | 在接收相对路径后，对其进行规范化（`normalize` 后检查是否仍以本地根目录为前缀），拒绝非法路径。 |
| 下载过程中应用被杀                              | 使用系统级后台下载能力（iOS 会调用 `URLSession` 的 completionHandler；Android 使用 `WorkManager` 或 `DownloadManager` 系统服务）恢复任务。 |

## 9. 总结

本需求分析明确了移动端文件下载模块的核心功能：通过接口获取目录树、导航浏览、元信息展示、保持服务器目录结构的本地下载、以及单/多文件下载支持。在实现时应重点关注目录结构镜像的准确性、多任务的并发与队列管理、异常恢复及存储空间控制。采用成熟的下载管理架构和系统级后台能力可以显著提升用户体验。后续可根据实际业务场景，扩展增量同步、断点续传等高级特性。
