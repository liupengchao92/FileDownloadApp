# 移动端文件下载需求分析

## 1. 引言
在 HarmonyOS 应用（Stage 模型，ArkTS）中，用户经常需要远程访问服务器上的文件资源，并进行选择性下载至本地以便离线使用。本需求针对“通过接口获取服务端文件目录，在移动端界面展示，并支持导航、单个/批量下载，且本地目录结构与服务端严格一致”的场景，进行详细的功能、交互、技术实现及异常处理分析。实际实现基于 `@ohos.net.http` 进行 API 请求，`@kit.BasicServicesKit` 的 `request.downloadFile` 进行系统级文件下载。

## 2. 总体目标
- **功能完整性**：实现服务端文件目录的树形/列表化展示，包含名称、类型、大小、修改时间等元数据；提供直观的目录导航（点击进入、面包屑/返回上级）。  
- **下载一致性**：支持将文件下载到移动端沙盒目录中，且本地文件夹层级、文件命名完全镜像服务端目录结构。  
- **下载灵活性**：支持单个文件下载和同时下载多个文件（多选批量）。  
- **可靠性与体验**：处理网络异常、存储空间、权限、并发控制等，并提供进度反馈。

## 3. 功能性需求详细描述

### 3.1 服务端目录获取与列表展示
**输入**：当前目录标识（如相对路径 `/` 或 `folderId`）  
**处理**：
- 请求接口获取当前目录下的所有子条目（子目录与文件）。
- 每个条目至少包含以下字段：
  - 名称（name）
  - 类型（type: `dir` / `file`）
  - 大小（size，仅文件有效，目录可为0或省略）
  - 最后修改时间（mtime，ISO 8601 格式）
  - 相对路径（relativePath，客户端拼接 `currentPath + name`，用于构建本地目录结构）
  - 已下载状态（isDownloaded，布尔值，标识本地是否已有该文件）
- 接口返回顺序即为展示顺序（服务端已排序：目录优先，同类型按名称字母序）。

**展示要求**：
- 使用列表视图（如 `List` ）显示。
- 目录和文件使用不同图标区分。
- 每行展示名称、类型（文件图标）、大小（格式化）、修改时间。
- 支持下拉刷新当前目录内容。

### 3.2 目录导航与路径切换
**行为**：
- 点击文件夹条目 → 进入该文件夹，重新加载并展示其内部内容。
- 提供面包屑导航（例如：`根目录 / 文档 / 项目报告`）点击任一级别即可快速跳转。
- 提供“返回上级”按钮（当不在根目录时显示）。
- 当前路径位置需清晰显示。

### 3.3 文件下载到本地沙盒并保持服务器目录结构
**目录结构镜像规则**：
- 移动端应用沙盒内指定一个根目录（`{context.filesDir}/ServerMirror`）作为所有下载文件的本地根。
- 对于服务端相对路径为 `folderA/sub/file.pdf` 的文件，下载后应保存在 `SandboxRoot/folderA/sub/file.pdf`。
- 若中间目录不存在，需递归创建。

**实现要点**：
- 每个文件的下载任务包含：
  - 源 URL（客户端从 `relativePath` 拼接：`{BASE_URL}/download/file?path={encodedPath}`）
  - 目标绝对路径（本地沙盒根 + 相对路径）
- 下载前检查目标路径所在目录是否存在，不存在则调用文件系统 API 创建目录。
- 覆盖策略：静默覆盖——先下载到 `.tmp` 临时文件，完成后 rename 到目标路径（防止下载中断产生损坏文件）。

### 3.4 单个及多个文件下载支持
#### 3.4.1 单个下载
- 每个文件条目右侧提供“下载”按钮（或长按菜单）。
- 点击后启动单个下载任务，显示下载进度（进度条或百分比），任务完成后更新状态。

#### 3.4.2 多文件批量下载
- 列表支持进入“编辑/多选模式”（长按或点击编辑入口），每个条目显示复选框。
- 提供“全选/取消全选”功能。
- 选中多个文件（仅文件可被选中；目录若被选中，根据需求可扩展为递归下载目录下所有文件，此处作为增强建议）后，点击“下载选中文件”按钮。
- 批量下载时，将所有选中文件的 `relativePath` 数组发送给服务端，服务端打包为 ZIP 返回，客户端下载后本地解压，保持服务端目录结构。
- 批量下载在并发队列中作为单个任务处理（不拆分为多个独立任务）。
- 提供批下载整体进度（已完成数/总文件数）及每个文件独立进度。

### 3.5 下载管理
- **下载队列**：管理等待、进行中、已完成、失败的任务（`waitingQueue` / `activeTasks` / `completedTasks`）。
- **任务状态**：等待（WAITING）、下载中（DOWNLOADING）、完成（COMPLETED）、失败（FAILED）。
- **进度通知**：通过观察者模式（subscribe/unsubscribe/notify）实时更新任务进度，UI 通过订阅事件刷新下载指示器。
- **用户操作**：支持取消单个任务。~~暂停/恢复未实现~~。
- **存储空间检查**：~~未实现~~（`checkStorageSpace()` 为存根，始终返回 true）。
- **失败重试**：对网络异常、服务器错误等任务提供自动重试机制（默认重试 3 次，间隔指数退避：1s、2s、4s）。

## 5. 接口定义

## 1. 获取文件列表

```
GET /api/files?path=<relativePath>
```

获取指定目录下的文件和文件夹列表，文件夹排在前面，按名称字母排序，隐藏文件（以 `.` 开头）不显示。

### 请求参数

| 参数   | 位置  | 类型   | 必填 | 说明                                       |
| ------ | ----- | ------ | ---- | ------------------------------------------ |
| `path` | query | string | 否   | 相对根目录的路径，空字符串或不传表示根目录 |

### 响应 200

```json
{
  "path": "",
  "files": [
    { "name": "documents", "type": "dir",  "size": 0,   "mtime": "2026-04-30T02:20:54.814Z" },
    { "name": "images",    "type": "dir",  "size": 0,   "mtime": "2026-04-30T02:20:55.068Z" },
    { "name": "readme.txt","type": "file", "size": 10,  "mtime": "2026-04-30T02:20:55.260Z" }
  ]
}
```

### 字段说明

| 字段    | 类型   | 说明                                  |
| ------- | ------ | ------------------------------------- |
| `name`  | string | 文件/文件夹名称                       |
| `type`  | string | `"dir"` 表示文件夹，`"file"` 表示文件 |
| `size`  | number | 文件大小（字节），文件夹为 0          |
| `mtime` | string | ISO 8601 格式的最后修改时间           |

### 错误码

- `400 PATH_TRAVERSAL` — 路径越权访问被拒绝
- `404 DIR_NOT_FOUND` — 目录不存在

## 2. 获取文件/目录信息

```
GET /api/files/info?path=<relativePath>
```

获取单个文件或目录的元信息。

### 请求参数

| 参数   | 位置  | 类型   | 必填 | 说明             |
| ------ | ----- | ------ | ---- | ---------------- |
| `path` | query | string | 是   | 相对根目录的路径 |

### 响应 200

```json
{
  "name": "readme.txt",
  "type": "file",
  "size": 10,
  "mtime": "2026-04-30T02:20:55.260Z"
}
```

## 3. 单文件下载

```
GET /api/download/file?path=<relativePath>
```

将文件以流式方式直接下载到本地。通过 HarmonyOS 系统下载服务（`@kit.BasicServicesKit` 的 `request.downloadFile`）发起，响应为二进制文件流。

### 请求参数

| 参数   | 位置  | 类型   | 必填 | 说明             |
| ------ | ----- | ------ | ---- | ---------------- |
| `path` | query | string | 是   | 源文件的相对路径 |

### 响应格式

`Content-Type: application/octet-stream`

响应为文件的原始二进制流。文件名通过 `Content-Disposition` 响应头返回。

### 错误码

- `400 NOT_A_FILE` — 只能下载文件
- `404 FILE_NOT_FOUND` — 源文件不存在
- `507 ENOSPC` — 磁盘空间不足

### 移动端调用示例（ArkTS）

```typescript
import { request } from '@kit.BasicServicesKit';

// 构建下载 URL
const url = `${BASE_URL}/download/file?path=${encodeURIComponent(sourcePath)}`;
const tmpPath = destPath + '.tmp';

// 通过系统下载服务下载
const task = await request.downloadFile(context, {
  url: url,
  filePath: tmpPath
});

task.on('progress', (received: number, total: number) => {
  if (total > 0) {
    const progress = Math.round((received / total) * 100);
    // 更新 UI 进度
  }
});

task.on('complete', () => {
  // 将 .tmp 文件 rename 到目标路径
  FileUtils.renameFile(tmpPath, destPath);
});

task.on('fail', (err: number) => {
  // 处理下载失败（错误码 1-8 映射为中文提示）
  FileUtils.removeTempFile(tmpPath);
});
```

## 4. 批量下载

```
GET /api/download/batch?paths=<encodedJSON>
```

批量下载多个文件/文件夹。支持文件和文件夹混合选择，所有文件会实时打包为 ZIP 压缩包并通过网络流式传输到客户端。通过 HarmonyOS 系统下载服务发起。

### 请求参数

| 参数    | 位置  | 类型   | 必填 | 说明                                                         |
| ------- | ----- | ------ | ---- | ------------------------------------------------------------ |
| `paths` | query | string | 是   | 相对路径数组的 JSON 字符串，经 `encodeURIComponent` 编码。可混合文件/文件夹 |

示例：`?paths=%5B%22documents%2Freport.pdf%22%2C%22images%2F%22%2C%22readme.txt%22%5D`

### 响应格式

`Content-Type: application/zip`

响应为 ZIP 压缩包的二进制流。

### 错误码

- `400 INVALID_PATHS` — 请选择至少一个文件或文件夹
- `400 NO_FILES` — 所选项目中无文件可复制
- `400 PATH_TRAVERSAL` — 路径越权访问被拒绝
- `507 ENOSPC` — 磁盘空间不足

### 移动端调用示例（ArkTS）

```typescript
import { request } from '@kit.BasicServicesKit';
import { zlib } from '@kit.ZlibKit';

// 构建批量下载 URL
const pathsJson = JSON.stringify(['documents/report.pdf', 'images/', 'readme.txt']);
const url = `${BASE_URL}/download/batch?paths=${encodeURIComponent(pathsJson)}`;
const zipPath = `${sandboxRoot}/.batch_${Date.now()}.zip`;

// 通过系统下载服务下载 ZIP
const task = await request.downloadFile(context, {
  url: url,
  filePath: zipPath
});

task.on('complete', () => {
  // 解压 ZIP 到沙盒根目录，保持目录结构
  zlib.decompressFile(zipPath, sandboxRoot).then(() => {
    // 删除临时 ZIP 文件
    fileIo.unlinkSync(zipPath);
  });
});
```

## 6. 移动端关键技术实现要点

### 6.1 本地沙盒目录结构维护
- **确定本地根目录**：`{context.filesDir}/ServerMirror`（应用沙盒内部 files 目录）。
- **创建相对路径目录**：使用 `FileUtils.ensureDir()` 确保目标路径的父目录存在（`fileIo.mkdirSync` 递归创建）。
- **文件写入**：通过 `@kit.BasicServicesKit` 的 `request.downloadFile` 系统下载服务，先下载到 `.tmp` 临时文件，完成后再 `rename` 到目标路径（防止下载中断产生损坏文件）。
- **路径安全**：`FileUtils.buildLocalPath()` 对相对路径进行 `normalize` 并拒绝含 `..` 的路径，防止路径遍历攻击。

### 6.2 多下载任务并发控制与队列
- `DownloadManager` 单例管理所有下载任务：
  - **三队列结构**：`waitingQueue`（等待队列）、`activeTasks`（进行中，Map）、`completedTasks`（已完成/失败，Map）。
  - **并发控制**：`MAX_CONCURRENT = 3`，`scheduleNext()` 从等待队列取任务填入空闲槽位。
  - **单文件任务**：`addTask(file, targetPath)` → 入队 → `executeSingleTask()` → 调用 `ApiService.downloadFile()`。
  - **批量任务**：`addBatch(files)` → 创建含 `batchInfo` 的单个任务 → `executeBatchTask()` → 调用 `ApiService.downloadBatch()` 下载 ZIP → `FileUtils.extractZip()` 解压。
  - **失败重试**：指数退避（延迟 `2^(retryCount-1) * 1000ms`，即 1s、2s、4s），最多 3 次。
  - **观察者模式**：通过 `subscribe`/`unsubscribe`/`notify` 向 UI 层推送 `DownloadEvent`（类型：`progress`、`statusChange`、`completed`、`failed`）。

### 6.3 UI 组件与状态管理
- **FileListViewModel**（单例）：管理文件列表、面包屑导航、多选状态、下载状态映射。订阅 `DownloadManager` 事件更新 `fileDownloadStates` 和 `batchState`。
- **FileRowComponent**：每行文件组件，订阅 `DownloadManager` 事件实时更新下载指示器（图标/进度环/完成标记/错误图标）。
- **Index.ets**：页面入口，包含顶部导航栏、多选操作栏、文件列表（`Refresh` + `List` + `ForEach`）。

## 7. 流程简述（用户视角 + 技术流）

### 场景1：浏览并下载单个文件
1. 用户打开文件管理页面 → `Index.aboutToAppear()` 初始化 `FileUtils` 和 `ApiService` → 调用 `viewModel.refresh()` 请求根目录内容 → 展示列表。
2. 用户点击文件夹 → `viewModel.navigateToDir()` 设置 `currentPath`、更新面包屑 → 调用 `refresh()` 请求子目录内容 → 更新列表。
3. 用户点击文件旁的下载按钮 → `FileListViewModel.startDownload(file)` → 计算本地目标路径 → `DownloadManager.addTask(file, targetPath)`。
4. `DownloadManager` 创建任务入队，`scheduleNext()` 调度执行 → `executeSingleTask()` 确保目录存在 → 调用 `ApiService.downloadFile()` 通过系统服务下载到 `.tmp` 文件。
5. 下载完成后 `.tmp` rename 到目标路径，通知 UI 更新为完成状态，显示 Toast 提示。

### 场景2：多选批量下载
1. 用户点击多选按钮进入多选模式，点击文件行勾选（`viewModel.toggleSelection()` 更新 `selectedFiles` Set）。
2. 点击底部"下载 (N)"按钮 → `FileListViewModel.startBatchDownload()` 收集选中的 `FileItem[]`。
3. 调用 `DownloadManager.addBatch(files)` → 创建含 `batchInfo` 的单个 `DownloadTask` 入队。
4. `executeBatchTask()` 执行：收集所有 `relativePath` → `ApiService.downloadBatch(paths, zipPath)` 下载 ZIP → 进度到 60% 切换为"解压..." → `FileUtils.extractZip()` 解压到沙盒根目录。
5. 解压完成，删除临时 ZIP，UI 显示"批量下载完成" Toast，2 秒后自动退出多选模式。

## 8. 异常场景及处理策略

| 异常场景                                        | 处理策略                                                     |
| ----------------------------------------------- | ------------------------------------------------------------ |
| 获取目录列表时网络断开                          | 显示错误提示及"重试"按钮（`viewModel.refresh()` 重新请求）。 |
| 下载过程中网络中断                              | 系统下载服务触发 `fail` 事件，`DownloadManager` 捕获后自动重试（指数退避，最多 3 次）。~~断点续传未实现~~。 |
| 存储空间不足                                    | ~~未实现~~（`FileUtils.checkStorageSpace()` 为存根，始终返回 true）。 |
| 目标路径已存在同名文件                          | 静默覆盖——先下载到 `.tmp` 文件再 rename，不提示用户。 |
| 路径遍历攻击（例如 relativePath 包含 `../../`） | `FileUtils.buildLocalPath()` 对路径 `normalize` 后检查是否含 `..`，拒绝非法路径。 |
| 下载过程中应用被杀                              | 使用 HarmonyOS 系统级下载服务（`@kit.BasicServicesKit` 的 `request.downloadFile`），由系统管理下载生命周期。 |

## 9. 总结

本需求分析明确了移动端文件下载模块的核心功能：通过接口获取目录树、导航浏览、保持服务器目录结构的本地下载、以及单/批量下载支持。实际实现采用 HarmonyOS 系统下载服务（`request.downloadFile`）进行文件传输，批量下载通过服务端 ZIP 打包 + 客户端解压方式保持目录结构。`DownloadManager` 单例管理下载队列（最大并发 3），支持指数退避重试和观察者模式的 UI 更新。未实现的功能包括：暂停/恢复、存储空间检查、断点续传、已下载状态持久化。
